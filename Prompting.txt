#Idea:
The *Kanban Board* project is a simple workflow management project. The user(Sathya) must be able to manage his task by dragging and dropping a task card across five columns named 'Backlog','Scheduled','Work In Progress','Testing','Deployed'.


#Drag and Drop:
The visual effect where the user would be able to pick a task from one column and move to the other.When each trasnition occurs it means a particular task's status changes from one state to another state.


#What is task
The set of instructions to be executed to accompish a desired outcome is known as task.


#What is a workflow management
The process of managing the tasks for effecient time management and work management.


#What is a *Kanban Board*:
A Kanban Board is a  project management tool used to visually represent the stages the task undergoes before the final deployment(production) in the project cycle. This helps the user to keep the in track of the tasks, prioritize them and manage them accordingly.


#Architecture overview:
The *Kanban Board* has 5 columns namely:
{definitions of each term}
i)'Backlog': list of tasks, ideas, or requirements that have been identified but are not yet planned for execution.
ii)'Scheduled': Tasks that have been prioritized and assigned a planned start date, resource, or sprint for execution.
iii)'Work In Progress': Tasks that are actively being worked on by team members and are currently under development.
iv)'Testing':Tasks that have been developed and are undergoing validation, quality assurance, and bug verification before approval.
v)'Deployed': Tasks that have passed testing and have been released or deployed to the target environment for end-user use.

#What the application does:
1.Sathya enters a task with its description {task_name,task_description,test_cases}
2.This task would be added to the 'Backlog' column
3.Now Sathya drags the task from 'Backlog' column and drops it to the 'Scheduled' column.
4.When a task is dragged and dropped into the Scheduled column, Sathya must provide the Start Date, End Date, and Effort Required (%). The Effort Required represents the estimated percentage of an 8-hour workday needed to complete the task, where 25% = 2 hours, 50% = 4 hours, 75% = 6 hours, and 100% = 8 hours. This information is used for planning, workload estimation, and tracking task commitments
5.After this Sathya drags and drops the task_card to the 'Work In Progress' column.
6.In the Work In Progress column, Sathya must be able to record the actual time spent on the task (in hours and minutes) and update the work status as either Pending or Completed. The logged time should be used to compare the actual effort against the estimated effort defined during scheduling.
7.Sathya now drags and drop the task_card in to the 'Testing' column. 
8.When the task_card is the 'Testing' column Sathya must be able to log the [Test_results] with {Start_Time,End_time,Test_Status{Passed|Failed}}. If the test result is passed move to deployment. If test result is failed the task_card goes to backlog again.
9.After this  Sathya drags the task_card from 'Testing' column and drops to the 'Deployed' column
10.When the task_card is in 'Deployed' column he must be able to log the [deployment details] with the details like {deployed_time,deployment_type{feature_update|new_version| subversion| minor_patch}.
11.Whenever Sathya clicks on the task_card that is appended to the any column{'Backlog'|'Scheduled'|'Work In Progress'|'Testing'|'Deployed'} he should be able to see information that is associated with it.
12. The movement of the task_cards are purely manual by the user
